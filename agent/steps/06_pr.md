# Step 6 — Commit, Push, and Open Pull Request

**Inputs:** `REPO`, `FORK_OWNER`, `ISSUE_NUMBER`, `ISSUE_SUMMARY`, `CHANGE_SUMMARY`,
            `VERIFICATION_REPORT`, branch `fix/issue-<ISSUE_NUMBER>`
**Outputs:** Open PR on the parent repo linking to and closing the source issue

---

## Actions

### 6.1 Stage and commit

```bash
cd <repo-name>
git add -A
git status   # confirm only the intended files are staged
git commit -m "fix: <one-line summary from CHANGE_SUMMARY>

<Two-sentence explanation of the root cause and what changed.>

Closes #<ISSUE_NUMBER>"
```

Commit message format:
- **Subject line**: `fix: <concise description>` (≤72 chars, imperative mood)
- **Body**: 2–4 sentences explaining root cause and approach
- **Footer**: `Closes #<ISSUE_NUMBER>` on its own line (no period)

### 6.2 Push to fork

```bash
git push origin fix/issue-<ISSUE_NUMBER>
```

### 6.3 Compose the PR description

Use this template — fill in every `<…>` from earlier step outputs:

```markdown
## Summary

<2–3 sentence description of the problem and the fix. Written for a reviewer
who hasn't read the issue. Non-jargon, past tense for problem, present for fix.>

## Root Cause

<One sentence explaining why the bug existed or the feature was missing.>

## Changes

- `<file path>`: <what changed and why>
- `<test file>` (new): <what the test covers>

## Verification

- [x] Existing test suite passes (`<TEST_CMD>`: <N> tests, 0 failures)
- [x] New test added: `<test name>` — covers `<what it tests>`

## Related

Closes #<ISSUE_NUMBER>
```

### 6.4 Open the pull request

```
tool: create_pull_request
owner:  <REPO owner>
repo:   <REPO name>
title:  "fix: <same subject line as commit>"
body:   <filled-in PR description template above>
head:   <FORK_OWNER>:fix/issue-<ISSUE_NUMBER>
base:   <DEFAULT_BRANCH>
draft:  false
```

Record the returned `PR_URL` and `PR_NUMBER`.

### 6.5 Confirm

Fetch the PR and confirm:
- `state` is `open`
- `body` contains `Closes #<ISSUE_NUMBER>`
- `head.ref` is `fix/issue-<ISSUE_NUMBER>`
- `base.ref` is `<DEFAULT_BRANCH>`

---

## Rules

- The commit body **must** contain `Closes #<ISSUE_NUMBER>` — this is a hard requirement.
- Do not squash or force-push after opening the PR.
- Do not add `[WIP]` or `Draft` unless `VERIFICATION_REPORT` shows failures
  (in which case you should not have reached this step).

---

## Log

Print when complete:

```
[STEP 6 ✓] Committed: "fix: <title>"
            Pushed  : origin/fix/issue-<ISSUE_NUMBER>
            PR      : <PR_URL>
            Status  : open | Closes #<ISSUE_NUMBER>
```
